Nexus 2.0 概念架构、交互体验设计与视觉规范

Nexus 2.0 将原本网状交错的概念重构为极其清晰的「底层资产 · 逻辑编排 · 终端消费」三级流水线，并将独立于网关之外的 Cursor IDE 切号与补丁归入独立轨道。保留全量核心能力，杜绝功能堆叠与入口绕路。

规范版本：2.0.0 · 生效日期：2026-10-16 · 覆盖范围：macOS & Windows 桌面端全体模块

零配置新手体验

新手在账号库添加第一个 Claude 账号时，系统自动归入预置的 claude/* 默认通道。加完号即可直接在「接入」页选模型，无需手动学习编排通道。

极致进阶灵活度

3 个 Claude 账号可拆分为 Claude-主力（绑定 2 个 Pro 号供日常写代码）与 Claude-备用（绑定 1 个测试号），并可将备用通道通过 Mesh 跨机出借给他人。

二、八大概念重构与交互边界定义

核心概念 核心职责定义 (只管什么) Nexus 2.0 体验升级
1. 账号 (Accounts) 管原始凭证与官方额度。负责订阅号登录、Token 刷新、窗口剩余百分比与重置倒计时。 新增「所属通道」胶囊与实时调用印记。可在卡片上直接调整分配所属分流通道。
2. 通道 (Channels) 管账号编排、路由前缀与跨机流转。连接底层账号与上层模型的逻辑桥梁。 打破平台 1:1 限制，支持新建自定义分流通道，卡片显示绑定账号迷你额度条。
3. Mesh 跨机算力 管通道的云端化 (借入与出借)。本机通道共享与远端算力挂载。 出借改为两段式状态机（显式确认才生成配对码）；借入通道显示为 ☁️ Mesh 云端通道。
4. 本地网关 (Gateway) 管 127.0.0.1 守护进程与安全口令。客户端底层通信总线。 化作左下角全局常驻的「网关引擎舱 (Gateway Engine Pod)」，带呼吸脉冲与控制台抽屉。
5. 接入 (Clients) 管本机编程客户端的接管与通道/模型指派。 提拔为默认高频首屏。已安装工具置顶展开，行内 [通道 ▾] → [模型 ▾] 直选即生效。
6. 模型广场 (Models) 管全通道可用模型目录与快速探针。 默认全量视图，顶部通道胶囊过滤，支持一键「指派给软件」与行内单轮试探。
7. 游乐场 (Playground) 管多模态会话验证与生成资产留存。 四个子项收拢为页面内顶部 Segmented 切换器，不再污染全局导航。
8. Cursor 专属 管 Cursor 本机登录态与 Agent 计费补丁。 合并切号池与账号库，支持热切/冷切与机器码重置；面板明确标识 ● 当前磁盘已生效。

1. 接入 (Clients) 模块规范

接入是 Nexus 最核心的高频首屏。用户打开软件，最关心的就是「我的写代码客户端现在连上了没有，走的是哪个通道的哪个模型」。

  • 卡片智能折叠置顶：已在本机检测到配置文件的软件（如 Claude Code）默认展开置顶；未安装或未检测到的软件折叠在底部，避免噪音。
  • 行内直选免重启：卡片行内提供 [通道 ▾] → [模型 ▾] 两级级联选择，改动后自动静默持久化到网关配置文件。由于客户端只连接到固定端点（如 http://127.0.0.1:8787/client/claude），客户端软件完全无需重启，下一轮对话即刻生效。
  • 行内探针与回显：点击 [测一下] 按钮，网关发送真实测试请求并回显：✓ 链路畅通 · 落点通道: [Claude-主力] → 命中账号: xxx@corp.com · 延迟 24ms。

2. 通道 (Channels) 与 Mesh 模块规范

通道是路由总线的调度中枢。分为本地逻辑通道与 Mesh 云端通道：

  • 1:N 逻辑通道编排：支持用户点击 [+ 新建本地分流通道]，自定义通道名称与路由前缀（如 claude-work/*），并可勾选绑定特定的账号子集，选择轮询负载均衡或高优容灾策略。
  • Mesh 云端通道同构抽象：远端机器通过配对码共享过来的算力，显示为 ☁️ Mesh 云端通道，带动态实时延迟（如 22ms），在上层客户端中与本地通道享有完全相同的选择体验。
  • 出借状态机两段式修复：彻底解决「点开出借弹窗就自动生成配对码」的缺陷，严格划分为「阶段一：只读配置」与「阶段二：显式确认出码」。

3. 模型广场 (Models Plaza) 模块规范

  • 全量视图默认呈现：一进入广场默认展示所有已就绪通道的模型，彻底告别以前「必须先选通道才能看」的死板体验。
  • 通道胶囊过滤条：顶部提供 [全部就绪通道]、[● 本地: Claude-主力]、[☁️ Mesh: 家里台式机] 等胶囊筛选，自动隐藏无凭证的空通道。
  • 一键指派给软件：每张模型卡提供 [试一下 (抽屉探针)] 与 [指派给软件]，点击可一键将该模型绑定给 Claude Code 或 Codex。

4. 游乐场 (Playground) 模块规范

  • 内部分段切换器：将原本占据侧边栏四个层级的子项，收进游乐场页面内部顶部：[💬 对话调试] [🎨 图片生成] [🎬 视频生成] | [🗂 本机生成资产]。
  • 双向联动工作台：在模型广场点击「在游乐场打开」，无缝自动填充对应的通道前缀与模型 ID，方便开发者深入多轮测试。

5. 账号库 (Accounts) 模块规范

  • 所属通道归属胶囊：在账号卡上展示 所属通道: [claude-work ▾]，可直接在卡片上修改所属通道。
  • 用量与重置倒计时：专注于官方订阅窗口剩余百分比与重置时间，与网关调用吞吐量清晰剥离。

6. Cursor 专属轨道 (切号与面板)

  • 统一切号轨道：合并 Cursor 账号库与切号快照，彻底废除繁琐的二次入池操作。所有 Cursor 账号一键立即可切。
  • 热切与冷切自由控制：
    • 未勾选重置机器码且 Cursor 正在运行：按钮为 [⚡ 热切上号]，十秒内静默生效，无需重启 IDE。
    • 勾选 [□ 切换时同时重置机器码 (需重启 IDE)]：按钮为 [↻ 重启并换号]，退出 Cursor、写入全新硬件机器标识并自动拉起。
  • Cursor 面板三档互斥：原生、CRSR、Sand，卡片明确高亮 ● 当前磁盘已生效 状态。

五、八大设计评审答卷闭环

针对此前设计评审稿提出的 8 大核心困惑，Nexus 2.0 给出的确定性架构答卷如下：

Q1: 第一屏应该是软件接入还是概览？
答：默认首屏设为「接入 (Clients)」。工具接入与模型指派是开发者每天操作最高频的行为，已安装软件置顶展开；概览作为系统总线大盘保留在菜单末尾。

Q2: 「通道」这个词还要不要？
答：必须保留并升华。通道不是平台的翻版，而是逻辑分流池（同平台多账号灵活拆分）与云端算力节点（Mesh 远端通道同构抽象）的核心枢纽。

Q3: 模型广场与接入职责如何划分？
答：接入管「客户端落地指派」（即改即生效免重启）；模型广场管「全量模型目录盘点与单轮快速探针」。模型广场支持一键「指派给软件」联动。

Q4: 网关开关放在哪里不抢点击？
答：从概览大卡片剥离，化作左下角全局常驻的「网关引擎舱 (Gateway Engine Pod)」，带呼吸绿灯，点击弹出独立控制台抽屉。

Q5: Mesh 借用与出借的状态机如何设计？
答：借用通道化身为「☁️ Mesh 云端通道」，带延迟显示；出借严格采用两段式状态机，只有用户显式点击「开启共享并生成配对码」才生成有效邀请码。

Q6: 账号官方额度与网关 Token 用量如何区分？
答：账号卡只展示官方订阅额度条与重置时间；网关转发产生的吞吐统计在网关引擎舱及右上角实时请求流抽屉展示，两套指标互不混淆。

Q7: Cursor 账号与切号池要不要合并？
答：合并为单一清单。废除二次入池门槛，所有可用 Cursor 账号支持一键热切或冷切。

Q8: Cursor 对话通道接不通如何呈现？
答：Cursor 属于独立 IDE 伴侣轨道，网关侧不再摆放失效的 Cursor 通道卡片，彻底避免坏死列表的负面感受。
